# 小游戏预留接口（MINIGAME-INTERFACE）

> 「戳泡泡 · 泡泡派对」**本期不实现**，仅**预留接口**，在**项目开发后期（P6）评估**是否实现。

## 1. 目标

以最小成本预留扩展点：当后期决定实现小游戏时，无需改动架构即可接入；若不实现，也不产生任何运行负担。

## 2. 预留接口（设计层）

### 2.1 抽象基类 `IMiniGame`
| 成员 | 说明 |
|---|---|
| `id()` | 游戏标识（如 `bubble-pop`） |
| `title()` | 显示名 |
| `createView(QWidget* parent)` | 返回该游戏的界面（Qt Widget） |
| `start()` / `pause()` / `stop()` | 生命周期 |
| `onFinished(score, meta)` | 结束回调（用于结算） |

### 2.2 注册与开关
- `MiniGameRegistry`：`registerGame(IMiniGame*)` / `availableGames()`。
- 设置项 `minigame_enabled`（默认关）。
- 右键菜单仅在存在可用游戏且开关开启时显示「小游戏」入口。

### 2.3 结算接口
- 通过 `GrowthService` 统一加好感/经验，并**限制每日养成收益上限**（沿用 whale「每日 3 局」思路）。
- 成就判定走 `AchievementService`（小游戏类成就预留，见 `GAMEPLAY.md`）。

## 3. 参考玩法规格（作为后期实现依据，非本期交付）

| 项 | 规格（来自 whale） |
|---|---|
| 棋盘 | 4×4 网格 |
| 目标类型 | 普通 / 星星 / 炸弹 三种泡泡 |
| 计分 | 连击加分 |
| 时长 | 30 秒一局 |
| 结算 | 三档评价 |
| 输入 | 鼠标点击 + 键盘方向键游标 + Enter 引爆 + Esc 退出 |
| 每日上限 | 3 局计入养成，超出只计分 |

## 4. 后期评估要点（P6 决策）

1. 主线玩法与梗聊天是否已稳定（优先级更高）。
2. 实现成本 vs 个人使用的实际收益。
3. 是否与学生项目「评优/演示」需求相关（若需要演示亮点则倾向实现）。

## 5. 约束

- 不引入任何第三方库（棋盘/动画用 Qt 自绘 + `QPropertyAnimation`）。
- 不实现时：`MiniGameRegistry` 为空，`minigame_enabled` 设置项隐藏或不显示入口（优雅降级）。

## 6. P6 评估结论（2026-10-01）

**决策：本期不实现「戳泡泡」小游戏。**

对照 §4 的三个评估要点：

| 评估要点 | 结论 |
|---|---|
| 主线玩法与梗聊天是否已稳定 | P1–P5 已验收，P6 以设置 / 打磨 / 测试 / 打包为主，不宜再引入新玩法分支 |
| 实现成本 vs 个人使用收益 | 「戳泡泡」需棋盘 + 计分 + 三档结算 + 每日 3 局上限 + 小游戏成就判定一整套；面向个人使用，收益有限 |
| 是否与学生项目「评优 / 演示」相关 | 本项目定位**面向个人使用**，无演示硬性需求 |

落地方式（严格按 §5「不实现」约束）：

- **不引入 `IMiniGame` 实现**，`MiniGameRegistry` 保持为空；全工程无 `MiniGameRegistry` / `IMiniGame` 定义（已核对）。
- 设置项 `minigame_enabled` **保留并默认关**；设置面板「小游戏」页以说明文案呈现（不隐藏，便于将来接入时无需改 UI 结构）。
- 小游戏类 **7 项成就**继续为 `AchMetric::MiniGameReserved`：只定义、不判定，成就墙显示「敬请期待」。
- 右键 / 托盘菜单**不出现**小游戏入口（符合 §2.2「仅在存在可用游戏且开关开启时显示」的优雅降级）。

**复评条件**：若后续出现演示需求或明确玩法扩展计划，可按本节 §2 的接口接入，无需改动现有架构。
